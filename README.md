### Задание 2. Класс `Transaction`

Класс описывает одну транзакцию. Все свойства (`id`, `date`, `amount`, `description`, `merchant`) приватные и задаются через конструктор с помощью promoted properties. Для чтения данных созданы getter-методы, сеттеров нет, поэтому после создания объект не изменяется.

В таблице по заданию 5 нужно выводить не только название, но и категорию получателя, поэтому получатель описан небольшим классом `Merchant` с полями `name` и `category`.

Дата хранится в объекте `DateTime`. Так как `DateTime` — изменяемый объект, `getDate()` возвращает его копию (`clone`), чтобы дату транзакции нельзя было поменять снаружи.

Количество дней с момента транзакции считается через `DateTime::diff()`:

```php
public function getDaysSinceTransaction(): int
{
    $now = new DateTime();
    return $this->date->diff($now)->days;
}
```

### Задание 3. Класс `TransactionRepository`

Класс отвечает только за хранение транзакций. Массив `$transactions` приватный, ключом служит `id` транзакции — так поиск и удаление выполняются сразу по ключу, без перебора:

```php
public function findById(int $id): ?Transaction
{
    return $this->transactions[$id] ?? null;
}

public function removeTransactionById(int $id): void
{
    unset($this->transactions[$id]);
}
```

`addTransaction()` выбрасывает `InvalidArgumentException`, если транзакция с таким `id` уже есть. `getAllTransactions()` возвращает `array_values()` — копию массива, поэтому изменить внутреннее хранилище через результат нельзя.

### Задание 4. Класс `TransactionManager`

Менеджер получает хранилище через конструктор и сам транзакции не хранит: в каждом методе он запрашивает их у репозитория через `getAllTransactions()`.

- `calculateTotalAmount()` — общая сумма всех транзакций;
- `calculateTotalAmountByDateRange()` — сумма за период, обе границы включаются. Строки дат проверяются через `DateTime::createFromFormat('Y-m-d', ...)`, при неверном формате выбрасывается исключение;
- `countTransactionsByMerchant()` — количество транзакций по названию получателя (без учёта регистра, `strcasecmp()`);
- `sortTransactionsByDate()` и `sortTransactionsByAmountDesc()` — сортировка через `usort()` и оператор `<=>`. Объекты `DateTime` можно сравнивать этим оператором напрямую.

Повторяющийся код вынесен в приватные вспомогательные методы `sumAmounts()` и `parseDate()`.

```php
public function sortTransactionsByAmountDesc(): array
{
    $transactions = $this->repository->getAllTransactions();
    usort($transactions, fn(Transaction $a, Transaction $b): int => $b->getAmount() <=> $a->getAmount());

    return $transactions;
}
```

### Задание 5. Класс `TransactionTableRenderer`

Класс объявлен как `final` и отвечает только за вывод. Метод `render(array $transactions): string` возвращает HTML-таблицу со столбцами: ID, дата, сумма, описание, получатель, категория, количество дней с момента транзакции. Каждая строка формируется приватным методом `renderRow()`, а текстовые данные экранируются через `htmlspecialchars()`.

В `index.php` таблица выводится одной строкой:

```php
<?php echo $renderer->render($manager->sortTransactionsByDate()); ?>
```

### Задание 6. Начальные данные

В `index.php` создано 8 получателей и 10 транзакций с разными датами, суммами, описаниями и получателями. Все транзакции добавляются в репозиторий в цикле:

```php
$repository = new TransactionRepository();
foreach ($transactions as $transaction) {
    $repository->addTransaction($transaction);
}
```

На странице выводятся все транзакции, сортировка по дате, сортировка по сумме и результаты вычислений. Над таблицами есть формы, через которые можно вручную добавить транзакцию, удалить её по `id`, найти по `id` или вернуть начальные данные. Чтобы изменения не пропадали при перезагрузке страницы, репозиторий хранится в сессии (`$_SESSION`). После отправки формы выполняется перенаправление, поэтому при обновлении страницы действие не повторяется.

### Задание 7. Интерфейс `TransactionStorageInterface`

Интерфейс содержит четыре метода: `addTransaction()`, `removeTransactionById()`, `getAllTransactions()` и `findById()`. `TransactionRepository` реализует его (`implements TransactionStorageInterface`), а конструктор `TransactionManager` теперь принимает интерфейс, а не конкретный класс:

```php
public function __construct(
    private TransactionStorageInterface $repository
) {
}
```

## Контрольные вопросы

**1. Зачем нужна строгая типизация в PHP и как она помогает при разработке?**
Без `declare(strict_types=1)` PHP молча приводит типы: например, строка `"10"` будет принята как `int`. Со строгой типизацией передача значения не того типа сразу вызывает `TypeError`. Это помогает находить ошибки ещё при запуске, а не по неправильным результатам, делает сигнатуры методов понятной документацией и улучшает подсказки в IDE.

**2. Что такое класс в объектно-ориентированном программировании и какие основные компоненты класса вы знаете?**
Класс — это шаблон, по которому создаются объекты: он описывает, какие данные хранит объект и что с ними можно делать. Основные компоненты: свойства (данные), методы (поведение), конструктор (`__construct`, инициализирует объект), константы, а также модификаторы доступа `public`, `protected`, `private`, с помощью которых реализуется инкапсуляция.

**3. Объясните, что такое полиморфизм и как он может быть реализован в PHP.**
Полиморфизм — возможность работать с объектами разных классов через общий тип, при этом каждый объект выполняет метод по-своему. В PHP он реализуется через наследование (переопределение методов родителя) и через интерфейсы. В этой работе `TransactionManager` вызывает `getAllTransactions()` у объекта типа `TransactionStorageInterface`, и ему неважно, какой именно класс реализует этот метод.

**4. Что такое интерфейс в PHP и как он отличается от абстрактного класса?**
Интерфейс — это контракт: список публичных методов без реализации, которые обязан реализовать класс. Отличия от абстрактного класса:
- интерфейс не содержит свойств и реализации методов, а абстрактный класс может содержать и то, и другое;
- класс может реализовать несколько интерфейсов, но наследоваться только от одного класса;
- методы интерфейса всегда `public`, в абстрактном классе могут быть `protected`.

Интерфейс описывает, *что* умеет объект, а абстрактный класс — общую основу для родственных классов.

**5. Какие преимущества даёт использование интерфейсов при проектировании архитектуры приложения? Объясните на примере данной лабораторной работы.**
Интерфейсы уменьшают связанность кода: классы зависят от контракта, а не от конкретной реализации. В этой работе `TransactionManager` зависит только от `TransactionStorageInterface`. Если понадобится хранить транзакции в базе данных или в JSON-файле, достаточно написать новый класс, например `DatabaseTransactionRepository implements TransactionStorageInterface`, и передать его в конструктор менеджера — код `TransactionManager` менять не придётся. Также для тестов можно подставить простое тестовое хранилище.
